# Decisions

Append-only. Format: `## SA-NNN: Title (YYYY-MM-DD) · Status: proposed | accepted | superseded by SA-MMM`.

## SA-001: Shape of the secrets agent (2026-11-17) · Status: accepted

**Context:** The hub's second agent creates and searches OpenBao secrets. openbao-platform
D-19 already fixed how it gets rights: the user's Cognito token, exchanged per request.

**Decision (agreed with the user 2026-11-17):**

| Question | Choice |
|---|---|
| Where secrets live | New KV v2 mount `apps/`: `apps/<product>/<service>/<environment>` |
| Environments | `dev`, `staging`, `prod` |
| Who creates | `openbao-secrets-writers` in dev/staging; only `openbao-admins` in prod; `openbao-secrets-readers` search only |
| Values | generated by the MCP server, or a placeholder plus a link to fill it in the OpenBao UI; never typed in chat |
| Search | keyed filters plus a shortlist ranked by the agent's own model (no external service) |
| AWS sync | right away, no approval; name proposed as `openbao/<product>/<service>/<environment>`, must stay under `openbao/` |
| Language | Python, like research-agent |
| Repo | public `github.com/edwardpius/secrets-agent` |

**Consequences:** OpenBao policies carry all group logic; the agent stays thin. The agent
must be a kagent declarative agent (Go runtime), since only that runtime forwards the user's
token to an MCP server. Spec 001 proves this before anything is written.

## SA-002: AWS sync reads all of `apps/`, and waits until every value is set (2026-11-17) · Status: accepted

**Context:** Spec 004. OpenBao policies can't grant reads based on a secret's metadata, and
secrets created with `ui` values start as placeholders.

**Decision:** ESO's role for the sync may read all of `apps/data`; it is bound only to ESO's
ServiceAccount in namespace `secrets-sync`, and only entries with `sync_aws = true` get an
ExternalSecret. A secret is synced only when none of its values is the placeholder.

**Consequences:** anyone able to create ExternalSecrets in `secrets-sync` could read any
`apps/` secret, so that namespace's RBAC allows only the reconciler. The reconciler must read values to
know whether one is still the placeholder, so its role reads `apps/data` too; it compares in
memory and never logs, stores or returns a value.

## SA-003: Data first, then metadata; writers may edit custom metadata in dev/staging (2026-11-17) · Status: accepted

**Context:** Spec 001's policy check. With metadata written first, OpenBao counts the data
write as an `update` (the path exists), so a create-only policy refused it.

**Decision:** `create_secret` writes the data first (`cas=0`, needing only `create`, so
nothing existing is overwritten), then the custom metadata. Writers (dev/staging) and admins
therefore have `update` on `apps/metadata/...`, limited to the `custom_metadata` parameter.

**Consequences:** a writer could change the description, team or ticket of another dev or
staging secret (not its value; OpenBao's audit log records who). They can already edit
dev/staging values in the UI (spec 001 REQ-06), so this adds no new power. Verified with
scoped tokens: create dev/staging 200, prod 403, overwrite 403, read data 403, other
metadata parameters 403.
